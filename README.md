# Лабораторна робота №10
## Тема: Production Python: Docker, CI/CD та захист проєкту
# Мета
Ознайомитися з підходами до підготовки Python-проєкту до production-oriented використання.
Навчитися:
- оформлювати Python-проєкт як пакет за допомогою `pyproject.toml`;
- створювати wheel (`.whl`) та source distribution (`sdist`);
- працювати з environment variables та Pydantic-settings;
- безпечно керувати secrets без збереження їх у коді;
- створювати `Dockerfile` та оптимізувати його з `.dockerignore`;
- будувати Docker image та запускати Docker container з передачею середовища;
- налаштовувати CI/CD pipeline у GitHub Actions з автоматичним запуском тестів, перевіркою покриття та збіркою;
- формувати документацію та підготувати проєкт до фінального захисту.

## Опис алгоритму (Варіант №3)
Проєкт є фінальним підсумком розвитку системи **«Інтернет-магазин» (Варіант 3)**.

### 1. Предметна область та структура даних
Основні сутності збережено та узгоджено з Lab_01, Lab_07, Lab_08 та Lab_09:
- **Category (Категорія)**: унікальний ідентифікатор `id`, назва `name`, зв'язок один-до-багатьох із товарами.
- **Product (Товар)**: `id`, `name`, `category_id`, `price`, `quantity`, `description`, обчислювана властивість `total_value` (`price * quantity`).
- Бізнес-операції: додавання товарів, пошук, фільтрація за категорією, обчислення вартості залишків, пошук найдорожчого товару, транзакційна покупка зі зменшенням кількості.

### 2. Пакетування та версіонування
- Проєкт оформлено згідно з PEP 518/PEP 621 через `pyproject.toml` з використанням `src-layout`:
  - `src/lab_10` та `src/online_store`
- Встановлено версію `1.0.0` (Semantic Versioning: `MAJOR.MINOR.PATCH`).
- Налаштовано збірку `wheel` та `sdist` за допомогою інструменту `build`:
  ```bash
  python -m build
  ```
- Отримано готові дистрибутиви в директорії `dist/`:
  - `lab_10-1.0.0-py3-none-any.whl`
  - `lab_10-1.0.0.tar.gz`

### 3. Конфігурація та безпека
- Усі параметри передаються виключно через **environment variables**:
  - `DATABASE_URL` — рядок підключення до бази даних (за замовчуванням `sqlite:///shop.db`).
  - `APP_ENV` / `ENVIRONMENT` — середовище виконання (`development`, `testing`, `production`).
  - `LOG_LEVEL` — рівень логування (`INFO`, `DEBUG`, `WARNING`).
  - `APP_NAME` — назва сервісу.
- Жодних паролів, токенів чи API-ключів у вихідному коді чи репозиторії не зберігається.
- Додано файл `.env.example`, а реальний `.env` внесено до `.gitignore`.
- Валідація конфігурації реалізована за допомогою `pydantic-settings` (`BaseSettings`).

### 4. REST API
Реалізовано надійний REST API на базі `FastAPI`:
- `GET /health` — обов'язковий health check сервісу, що повертає статус `ok` та поточне середовище.
- `GET /` — інформаційний корінь API.
- `GET /categories`, `POST /categories` — робота з категоріями товарів.
- `GET /categories/{id}/products` (та `/categories/{category_id}/products`) — товари певної категорії.
- `GET /products` — список усіх товарів із підтримкою фільтрації (`?category=...`) та пошуку (`?search=...`).
- `GET /products/{id}` — отримання товару за ідентифікатором.
- `POST /products` — створення нового товару з валідацією даних.
- `PATCH /products/{id}` — часткове оновлення інформації про товар.
- `DELETE /products/{id}` — видалення товару зі складу.
- `POST /products/{id}/purchase` — транзакційне списання кількості товару з перевіркою залишків на складі.
- `GET /statistics/inventory-value` — сумарна вартість складу.
- `GET /statistics/most-expensive` — визначення найдорожчого товару.

### 5. Контейнеризація за допомогою Docker
Створено оптимізований `Dockerfile` на базі легко вагового образу `python:3.12-slim`:
- Встановлено змінні середовища `PYTHONDONTWRITEBYTECODE=1` та `PYTHONUNBUFFERED=1`.
- Описано виключення в `.dockerignore` (`__pycache__`, `.git`, `.venv`, `.env`, тести).
- Налаштовано команду `HEALTHCHECK` із запитом до `http://localhost:8000/health`.
- Вказано порт `EXPOSE 8000` та команду запуску через production ASGI-сервер `uvicorn`.

**Збірка та запуск Docker-контейнера:**
```bash
# Збірка образу
docker build -t online-store:1.0.0 .

# Запуск контейнера з прокиданням порту та передачею змінних
docker run -d -p 8000:8000 -e ENVIRONMENT=production online-store:1.0.0
```

### 6. Неперервна інтеграція (CI/CD) у GitHub Actions
Файл `.github/workflows/ci.yml` налаштований для автоматичної перевірки при кожному `push` та `pull_request`:
1. Checkout коду через `actions/checkout@v4`.
2. Встановлення середовища Python через `actions/setup-python@v5`.
3. Встановлення проєкту та тестових залежностей.
4. Запуск повного набору автоматичних тестів з контролем покриття `pytest -v --cov=lab_10 --cov-report=term-missing`.
5. Збірка дистрибутивів `python -m build`.
6. Перевірка цілісності артефактів `dist/`.

### 7. Сценарій демонстрації на захисті
1. **Перевірка кодової бази та тестів**:
   ```bash
   pytest -v --cov=lab_10
   ```
   Всі 21 тест проходять успішно, покриття коду > 88%.
2. **Збірка пакета**:
   ```bash
   python -m build
   ```
3. **Локальний запуск через CLI**:
   ```bash
   python -m lab_10.main
   ```
4. **Запуск та перевірка контейнера**:
   ```bash
   curl http://localhost:8000/health
   # Відповідь: {"status":"ok","app_name":"Online Store Manager","environment":"production"}
   ```
5. **Демонстрація Swagger UI**: відкриття `http://localhost:8000/docs` та демонстрація транзакційного продажу товару.
